# 白色主体保护：根因、数学模型与专项验证

## 1. 根因不是“白色没有对应豆”，而是占位掩码提前删掉了它

问题版本来自提交 `7a8714608cf8d39b7785487087534e77617bb394`。`baseline-v2-engine.js` 保留该版本的 `engine.js`，仅修正模块导入路径。原代码先从 RGBA 得到 Lab，再按背景泛洪将部分格子标记为 `skip=1`，之后将它们传成 `null` 交给选色器。选色器只能选择豆的颜色，不能恢复已被标成空白的位置。

在网站路径中，去背景默认开启；设置缺省值也恢复为开启，默认色差容差为 20、最高为 60。图像先缩到最终豆子网格，再去背景。旧背景模型只要求四个角中的两个颜色相近，便将其用作背景参考，并从所有边缘尝试四邻域泛洪：

`Cτ = {p : ΔE76(Lab(Ip), b) ≤ τ} ∪ {透明格}`

`R = Cτ 中与图像边缘相连的四连通区域`

`mₚ = 0 （p∈R），否则 mₚ = 1`

这是一种“颜色阈值 + 连通区域重建”启发式，不是对象识别。存在四个风险：

1. 灰线经过降采样后与白底混合，变得更接近白色，失去阻止泛洪的作用。
2. 较大的 `τ` 将灰线、米白色衣服和白背景同时视为背景候选。
3. 白物接触图像边缘时，合法前景本身就是泛洪起点；两个角的共识也可能来自前景。
4. 同色物体和背景本来就缺少可辨识证据，任何单纯颜色阈值都不能推断用户希望保留哪块。

**上一轮研究的遗漏：**上一轮 12 图/252 条评估全部设置 `removeBackground:false`，只验证取样、选色和空间整理。那些结果不能证明背景掩码正确。本轮增加独立的前景真值和误删指标，不再用总颜色误差掩盖占位错误。

## 2. 先区分三个不同的数学问题

### 2.1 观测与不可辨识性

经典 alpha 合成写为 `Iₚ = αₚFₚ + (1−αₚ)Bₚ`。只有一张 RGB 图时，每个位置有三个观测值，却有前景三通道、背景三通道和 alpha 共七个未知数，因此需要先验或用户约束。[Levin、Lischinski、Weiss 的原始论文](https://webee.technion.ac.il/people/anat.levin/papers/Matting-Levin-Lischinski-Weiss-CVPR06.pdf)明确讨论了该欠定问题。

如果 `F=B=白色`，则任意 `α` 都得到同一白色 `I`。这不是换一种滤镜或调小阈值就能消除的信息缺失。本测试包含完全相同 RGBA 的“全白画面都要豆”和“白底只要中心白物”两个意图掩码，任何只读取该图像的确定性算法都不可能同时还原两种意图。

原生 PNG 的透明通道属于额外已知信息，应优先使用。白色 RGB 与透明 alpha 是不同维度；白色不得自动等价为透明。

### 2.2 前景/背景分割

令 `mₚ∈{0,1}` 表示是否保留前景。经典有种子的图割模型为：

`E(m) = Σₚ Dₚ(mₚ) + λ Σ(p,q) wₚq [mₚ≠m_q]`

其中 `D` 是前景/背景证据；`w` 通常随边界对比增大而减小；用户种子作为不可违反的约束。[Boykov–Jolly 2001](https://www.csd.uwo.ca/~yboykov/Papers/iccv01.pdf)用图割求所定义能量的最优解；“最优”是相对于模型和种子而言，不是相对于人类语义必然正确。[GrabCut 2004](https://www.microsoft.com/en-us/research/wp-content/uploads/2004/08/siggraph04-grabcut.pdf)进一步交替更新颜色模型与分割，并采用交互初始化。

本站本轮没有实现完整 GrabCut、图割或闭式抠图，也没有用这些论文的优化保证包装自己的启发式。实际采用更保守的**源图分辨率、边缘约束、带拒绝机制的区域重建**。无法可靠分割时，保留像素比默默删掉主体更符合制作图纸的要求；用户主动选择去底时才尝试删除。

### 2.3 固定占位下的离散颜色量化

给定占位 `m` 后，只在 `mᵢ=1` 的豆格上选择色号 `zᵢ`，且全部色号来自可用库存 `P`、用色数不超过 `K`：

`min Σᵢ:mᵢ=1 wᵢ ||xᵢ−c(zᵢ)||² + λ Σ(i,j) aᵢⱼ [zᵢ≠zⱼ]`

`zᵢ∈S⊆P，|S|≤K`

第一项保留颜色特征，第二项抑制低对比碎片；`aᵢⱼ` 在强边界处较小。这是上轮的受限色卡量化与 Potts 空间代价，使用贪心选色、受限中心更新和局部标签更新，不保证全局最优。CIE 的正式定义将 ΔE76 定义为 Lab 空间欧氏距离；它衡量颜色差异，**不定义前景身份**。[CIE 定义](https://cie.co.at/eilvterm/17-23-077)

## 3. 本轮的组合方式

实际流水线按依赖次序拆开，不声称已经联合求得全局最优：

`源 RGBA → 占位/背景处理 → alpha 预乘取样 → 可选风格 → 受占位约束的色卡量化 → 图纸`

网站另外提供源图主体范围建议与用户框选，作为上述流水线之前的裁取范围。建议框来自透明度或可靠的背景分割；证据不足时保留整图。它没有语义模型，不等于已识别“人、衣服或动物”。当前数值实验直接调用纯转换流水线，不把人工框选或包围框当作自动语义识别证据。

- 默认保留不透明内容，保留合法白色豆；原生透明处仍为空格。
- 主动去底时，先在较高的源图分辨率上判断背景，避免降采样先抹掉灰色轮廓。
- 不把所有边缘像素无条件作为背景证据；检查边界一致性，设置局部梯度屏障，采用受约束的四连通重建。
- 缺少前景证据、颜色/边界不可靠或遇到原生透明信息时，使用明确的保守结果和诊断，而不是返回一张悄悄删空的图纸。
- 分割后用 alpha 预乘面积取样。目标豆格的 alpha 覆盖率由 `āᵢ=Σₚκᵢₚα'ₚ` 给出，`κ≥0、Σκ=1`；按阈值 `100/255` 决定该格是否存在。颜色取样使用 alpha 权重，避免透明像素隐藏 RGB 污染边缘。
- 在图纸网格上不再重复按白色泛洪。量化器只能在固定可见格上改颜色，不能把白色变成 `null`。

二元形态学重建可写作 `R₀=J，Rₜ₊₁=(Rₜ⊕B)∩K`，直到不再变化；`J` 是可信边界种子，`K` 是未被屏障挡住的候选背景。这只提取由种子到达的连通部分。[Vincent 1993 的原始论文](https://telin.ugent.be/~sanja/StudentProj/Literature/vincent-93.pdf)给出形态学重建的定义及算法背景。本站还加入经验性的边界置信与拒绝条件；形态学本身不赋予语义正确性。

结构先于取样的处理顺序也与 [Kopf、Shamir、Peers 的内容自适应缩小研究](https://johanneskopf.de/publications/downscaling/)中“常规缩小可能损失细线与边缘”的问题一致；本站并未实现该论文的 EM 取样核优化。

具体阈值、拒绝条件和源代码散列以本轮 `background-segmentation.js`、`pattern-pipeline.js` 及结果 JSON 为准。源图已被拍摄成完全相同的白色时，保守模型仍无法恢复不存在的边界证据，需要透明原图或人为指定范围。

## 4. 验证协议

首轮 12 个原创程序绘制样例在观察结果之前固定，7 个开发、5 个保留；每个样例分别绘制原图与“需要豆的位置”真值掩码。首轮保留组在参数冻结后首次运行，其原始数据保留在 `round1/results/`。

开发组覆盖：白衣灰线、灰线围白、白物触边、透明底白物、全白不透明图、白物白底不可辨识、高对比彩色主体。保留组使用不同尺寸与几何形状，覆盖米白背景白碗、白星形、透明底白物占两角、前后景各占两角、触底白帽。

随后，原项目已有的独立 9×9 黑环回归测试发现新算法在原尺寸图上增生白色晕边：期望保留25格，实际保留65格。修复依据是这项集成失败，不是保留组调参。屏障改为只标记边界中远离背景的一侧，并修正形态闭合的图像外边界处理。**为避免重复使用已看过的保留组作为独立证明，原12例全部转为回归组**。

第二轮重新固定4个新保留例：13×13原尺寸白十字、17×13细斜灰框、19×15带封闭内孔的白环、15×11透明底L形。这些结果仅在第二轮参数冻结后首次观察；最终报告分开呈现12例回归和4例新保留。白环故意检测“外界连通去底无法推断封闭内孔意图”的限制，并不要求自动算法凭语义猜中。

每例比较旧版容差 20/60、新版默认保留、新版主动去底容差 5/20/60。新版通过网站实际 `convertSourceToPattern` 执行，减少评估脚本与产品路径差异。除原尺寸十字为1倍外，源图为目标网格四倍，和网站预处理上限相容；浏览器解码/绘制另行验收。

真值按独立源掩码的面积覆盖投到目标网格，阈值与 alpha 一样为 `100/255`。白色真值子集要求源前景 RGB 各通道至少 230、通道极差不超过 20，再按覆盖率投影。该定义固定在看结果前，不根据输出改阈值。

| 指标 | 定义 | 防止的误导 |
|---|---|---|
| 白色前景误删率 | 输出为空的真值白格 / 全部真值白格 | 专门反映“白色豆消失” |
| 全部前景误删率 | 输出为空的真值前景格 / 全部真值前景格 | 不只保护白色而损伤别处 |
| 背景残留率 | 输出非空的真值背景格 / 全部真值背景格 | “全部保留”不会被包装为抠图成功 |
| 前景 IoU | 保留前景与真值前景的交并比 | 同时计入误删和残留，但不能取代分别报告 |
| 保留豆数 | 非空格数 | 发现整图删空或异常满图 |

没有该类真值时比率记为 `null`，不是 0。歧义对照单独报告，不将它伪装为可以自动推断的普通正确分割题。

## 5. 复现与范围

```text
python research/white-preservation/prepare-fixtures.py
node research/white-preservation/run-benchmark.mjs --split=regression
node research/white-preservation/run-benchmark.mjs --split=heldout
node research/white-preservation/summarize-results.mjs
python research/white-preservation/render-comparison.py
```

PNG、原始 RGBA、源掩码与各自 SHA-256 保存在 `data/` 与 `fixtures.json`。代码 SHA-256 使用 UTF-8 并规范 CRLF/CR 为 LF，避免 Windows Git 换行造成假差异。结果为 JSON、CSV、自含 HTML，包含每例而非只挑选成功案例。

本专项的带真值评估属于合成形态测试，不能代替真实用户照片或人工标注数据库。没有实物拼装试验，也没有测定人类对照片语义的识别率。它验证的是白色占位安全性和可控背景删除的工程边界。
