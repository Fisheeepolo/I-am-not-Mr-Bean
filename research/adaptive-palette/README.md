# v4.3 自适应色号预算（本地开发）

## 问题与修改

v4.2 有两条增加近似色的路径：最近色集合不超过 K 时直接全收；超过 K 时，只要平方色差有非零收益，就继续加色至 K。因此上限越大，抗锯齿、微弱色阶可能获得独立色号。空间平滑可以减少碎豆，但不等于选择更少的色号。

v4.3 保留硬约束 |S|≤K，将均衡和好拼模式的调色板贪心收益改为“超过容差部分的误差改善”。细节模式保持旧行为；`adaptivePalette:false` 为消融开关。

对源颜色 r、物理色卡 c：

- 原始代价 d_rc = ΔE2000(r,c)²，m_r = min_c d_rc。
- 选色代价 q_rc = max(0, d_rc − m_r − τ_r²)。
- 均衡 τ=3，好拼 τ=5，细节 τ=0；已有显著性保护单元 τ=0。
- 初始色仍用原始加权代价最小的色卡，避免用保护细节的颜色代表整张底色。
- 贪心增加使 Σ_r w_r min_(c∈S) q_rc 下降最多的色号；没有收益便停止，无需凑满 K。
- 后续 medoid 精修、MRF、孤岛优化使用原始色差，透明占位不变。

这是容差停止准则，不是复现 label-cost graph cuts，也不是语义分割。参考 Delong 等对“空间平滑”和“少用标签”是两个不同目标的讨论：
https://www.csd.uwo.ca/~yboykov/Abstracts/ijcv10_lc-abs.shtml

τ 是本轮工程默认值，不宣称是普适的可见阈值。此处是平方误差超额容差，不能解读为每颗豆的最终 ΔE≤τ；后续空间优化也可能增加局部色差。全局最优无保证。显著性保护在取样近似分箱时采用保守 OR 汇总，可能保留多余颜色。

## 验证

`node --test tests/adaptive-palette.test.mjs`

- 80×80 轻微红色色阶（20 个相近输入色、人工色卡）：旧最终输出 2 色；新输出在 8/16/20 上限均为 1 色。新平均 ΔE2000=1.10126。
- 宽灰度渐变：保留 16 色，平均 ΔE2000=0.54617。
- 单颗高反差豆、显著性标记的低反差豆、透明格、缺货色卡、确定性与输入不变性均通过。
- 原孤岛单元测试明确关闭自适应选色，以独立检验孤岛阶段，而非要求新选色阶段先制造孤岛。
- 全套测试 69/69 通过；构建及 Worker 校验通过。

`node research/adaptive-palette/evaluate.mjs`

使用既有开发集 7 张（3 张照片、4 张人工图案），16/20 两个上限，共 14 对比较，实际 MARD 色卡。原始输出见 development-results.json。未使用保留集调参，未覆盖旧研究结果文件。

- dev-low-contrast：两档均从 3 色到 2 色；平均 ΔE2000 从 3.274528 到 3.274531。
- 3 张真实照片：两档色数均不变，说明此改动未对丰富照片强行减色。
- dev-highlights：2 色保持不变。
- dev-eyes-lines（20 上限）：17→18 色，是已知反例。新旧集合与空间分配不同，不能宣称最终色数必然下降。需要更多真实单色标志样本再评估边缘抗锯齿归并。
- 所有对照占位完全相同。

目前最适合改善微弱近似色阶；不将粉色边缘、真实阴影或文字笔画一律视为噪声。已保存图纸不自动重写；用户点击生成后应用新算法。
